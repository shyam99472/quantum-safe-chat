PQ-Adaptive Ratcheting for TreeKEM-Based Secure Group Chat

Single-file demo summary for guide / reviewer / project presentation

Init Classical Heal PQ Batch Heal

This project implements a hybrid post-quantum real-time chat application with direct secure messaging, TreeKEM-style secure group state, adaptive healing, and a paper-facing metrics panel. The current novelty direction is PQ-Adaptive Ratcheting: PQ remains part of the group-security baseline, while the scheduler controls when lightweight healing or stronger batched PQ refreshes should occur.

2. Cryptographic Design

Direct Chat

  • Authentication with Dilithium / ML-DSA signatures on the handshake transcript.
  • Hybrid key establishment using ECDH + Kyber / ML-KEM.
  • Session key derivation with HKDF and AES-256-GCM for message/file encryption.
  • Forward ratchet with per-message key evolution and replay controls.

Group Chat

  • TreeKEM-style group state with epochs, direct path, and copath metadata.
  • Baseline hybrid wrapping for group root-key distribution using ECDH + Kyber when available.
  • Sender-specific ratchets derived from the current epoch root key.
  • AES-GCM with authenticated metadata binding group ID, epoch, membership version, sender ID, and message index.
Mode Meaning
Init Initial group setup with baseline hybrid recipient wrapping and epoch 1 state creation.
Classical Heal Lightweight scheduled healing mode with lower-cost refresh behavior while retaining PQ baseline wrapping.
PQ Batch Heal Stronger adaptive recovery mode with explicit subgroup batching semantics and hybrid ECDH + Kyber recipient wrapping.

3. Novelty Direction

The project does not treat PQ as an optional add-on. Instead, PQ is part of the baseline secure group key-distribution path, while adaptive ratcheting controls how often and how aggressively stronger healing should occur. This supports a research claim centered on balancing post-quantum security, bandwidth overhead, and healing frequency.

Design principle: “Do not switch PQ security on and off. Keep PQ in the baseline, then adapt the recovery schedule and batching intensity.”

4. Adaptive Scheduler

  • Tracks group traffic since last heal and since last PQ heal.
  • Escalates from NO_HEAL to TREE_HEAL_CLASSICAL on lighter thresholds.
  • Escalates to TREE_HEAL_PQ_BATCH for larger traffic windows, periodic PQ refresh windows, membership changes, or suspected compromise.
  • Preserves manual reviewer controls using the visible C and PQ buttons.

5. PQ Batch / mKyber-Style Semantics

  • PQ Batch builds explicit subgroup batch metadata instead of sending a single undifferentiated PQ label.
  • Each recipient is mapped to a batchId.
  • Control payload carries batch plan, batch count, recipient-to-batch mapping, and TreeKEM path-coverage metadata.
  • Recipient unwrap uses hybrid ECDH + Kyber secret derivation, while the payload structure reflects batched healing semantics.

6. PCS-Oriented Recovery

  • Membership changes are treated as security-relevant events and feed the scheduler.
  • Suspicious decryption failures can mark the group for stronger PQ recovery.
  • Admin-side open-group state can automatically push a PQ recovery epoch when these signals are triggered.
